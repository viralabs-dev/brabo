    Модель команды и поток результатов

    Сводный контекст сессии проектирования модели команды (авг/2026), проверенный по реальному состоянию продукта. Формальная спецификация живёт в packages/contracts/fluxo.yml; этот документ объясняет решения. Структурное решение: ADR 0085. Родственные части: apps/api/config/gates.yml (ADR 0054) и agent-areas.ts (каталог, FASE 18).

    Происхождение

    Модель переводит карту профессий высокоэффективной команды поставки (Arquiteto, Tech Lead, PO/PM, Staff, SRE/Platform, DevOps/Infra, QA/SDET, AppSec, Data/Analytics Engineer, UX, Delivery, DBA) в агентов Brabo по двум критериям:

    1. Отдельная роль существует, только когда есть отдельный результат И отдельный gate. Разделение по оргструктуре порождает handoff без выигрыша.
    2. Каждый переход между ролями — объявленный gate с проверкой скриптом, никогда ручной записью (урок Фазы 10/13).

    Принцип, проявившийся при разделении: почти любое разделение — сначала по РЕЗУЛЬТАТУ и МОМЕНТУ, и лишь затем (возможно) по агенту — QA и AppSec получают момент проектирования, сохраняя одного агента; analytics родился как новый выход medicao, прежде чем стать ролью. Роль материализуется, когда её артефакт уже циркулирует, никогда раньше, — кроме случаев, когда владелец продукта решает ПРЕДВОСХИТИТЬ построение, не дожидаясь органического триггера, как он сделал для analytics/delivery-metricas (ADR 0089): обе стали status: active как СКРИПТ отчёта (analise:funil), никогда агентом — форма, которую критерий разделения уже предписывал.

    Решения владельца продукта

    • Engineering Manager: удалён. Между агентами нет управления людьми.
    • Criativo — входная дверь — превращает свободный разговор в бизнес-потребность. Поглощает discovery UX.
    • Psicólogo и Anamnese: em-refinamento. Код активен, вне формального потока до переопределения результатов. Созданные открытые пункты: предложение поднять max_parallel (RN-086) остаётся без автора, а триггер активации Staff остаётся сиротой.
    • Delivery поглощён Harness (оркестрация) + измерением (ЧАСТИЧНЫЙ DORA, поставленный как отчёт — реальная воронка, реальный lead time, реальная deployment frequency; MTTR и change failure rate остаются status: lacuna, зависящими от сигнала реального инцидента — ADR 0089); DBA поглощён Dev Lead (миграция) и Platform (tuning).

    Инварианты потока

    1. Ни одного артефакта без объявленного адресата.
    2. Ни одна роль не начинает без полных входов — недостаток порождает возврат с причиной, никогда не молчаливое допущение.
    3. Каждый переход — gate декларативного реестра (ADR 0054).
    4. Обратная петля обязательна: телеметрия → Arquiteto и метрики продукта → PO — это артефакты с адресатом.
    5. Граница Arquiteto × Dev Lead: решение, которое помещается в обратимый PR, принадлежит Dev Lead; необратимое решение — Arquiteto.
