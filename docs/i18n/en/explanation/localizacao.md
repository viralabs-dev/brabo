# Localization

Brabo speaks four languages in the documentation and in the interface, and
**Brazilian Portuguese is the source and the default** of both products ([ADR 0216](../adr/0216-quatro-idiomas-com-pt-br-como-fonte.md)).
All new text is born in pt-BR; the other languages are translations of it.

**Exception (ADR [0260](../adr/0260-doc-dos-repos-de-codigo-so-em-ingles.md)):** this rule applies only to `brabo`, the customer's front door. The documentation of the ten code repositories is **English-only**: a sibling page in English carries `idioma_original: en` in the frontmatter and has no `docs/i18n/`. Their `CLAUDE.md` and `.claude/` stay in pt-BR.

## Languages and codes {#idiomas-e-códigos}

| language | code | plural forms (`Intl.PluralRules`) | note |
|---|---|---|---|
| Português (Brasil) | `pt-BR` | one, many, other (+ mandatory `_zero` in the interface) | source |
| English | `en` | one, other | [English notes](localizacao-en.md) |
| Русский | `ru` | one, few, many, other | [Russian notes](localizacao-ru.md) |
| 简体中文 | `zh-Hans` | other | [Chinese notes](localizacao-zh-hans.md) |

The codes are the same in Docusaurus, in i18next, in `<html lang>` and in
`users.locale`. The site's local search uses its own (`pt`, `en`, `ru`, `zh`).

On the site, the language selector sits in the top bar (`localeDropdown` in
`website/docusaurus.config.ts`), with the labels above, and takes you to the same
page in the chosen language; each language lives under its own path (`/en/`,
`/ru/`, `/zh-Hans/`; pt-BR at the root of the stage).

## Resolving the interface language {#resolução-do-idioma-na-interface}

The choice saved in the account **always wins** and is never overwritten by detection.
Without a choice, the browser language suggests
(`resolverIdiomaDoNavegador`, `apps/web/src/lib/idioma.ts`):

- `pt*` → `pt-BR`;
- `zh`, `zh-CN`, `zh-SG` and `zh-Hans*` → `zh-Hans`;
- `ru*` → `ru`;
- `en*` → `en`;
- anything else — German, traditional Chinese (`zh-TW`, `zh-Hant`) — → `pt-BR`.

The language of the agents' REPLIES is another preference, with its own mechanism
(ADR 0177), and does not depend on the interface language.

## Missing text {#o-texto-que-falta}

- **On the site**, a page without a translation in a locale is served from the pt-BR
  source, at the same address, and a banner at the top SAYS so in the reader's
  language. A translated page whose source changed after the translation states the
  translation date and that the original changed.
- **On the site, a sibling page with `idioma_original: en`** is the source itself on `/en/`, with no banner; on pt-BR, `ru` and `zh-Hans` the site serves the SAME English source with the banner "this page only exists in English". If the sibling still has the locale's translation, it applies there (mixed state, page by page).
- **In the interface**, text is never missing: key and plural parity is
  measured, and `fallbackLng` is pt-BR.

Every translated page carries `traducao_de: <SHA>` in its frontmatter — the last
commit of the source it translates. That is what separates "up to date" from "stale". Today's
measurement is in [Translation parity](../reference/paridade-de-traducao.md),
generated by `pnpm docs:generate`.

The Reference sidebar labels and the top bar labels come from `website/sidebars.ts` and each locale's `navbar.json`/`current.json`; since ADR 0219 the content of the `reference/` pages is translated too, generated block included, and only the parity page stays out.

## What is never translated {#o-que-nunca-se-traduz}

- **Brabo**, and the agent and role names from the [glossary](../glossary.md)
  (Criativo, PO, Arquiteto, Dev Lead, Infra Lead, `owner`, `maintainer`…);
- user data (project names, messages, artifacts);
- commands, paths, names of variables, branches and events;
- RN and ADR numbers and the `{#rn-NNN}` anchors.
