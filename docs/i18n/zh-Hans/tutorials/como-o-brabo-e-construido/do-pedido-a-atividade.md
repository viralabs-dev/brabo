# 从请求到任务

**适合谁：** 收到零散请求（来自负责人、客户或测试发现）、并希望把它们变成无需开会就能开始的工作的人。

**读完之后你可以：** 写出一个别人或智能体无需提问就能执行的任务，并判断它何时可以进入一个轮次。

## 三个层级，各司其职

- **史诗：** 持续数周的目标。例如：“企业登录”。
- **任务：** 可以独立交付并可验证的最小单元。例如：“ATV-001：登录支持 SSO”。
- **卡片：** 任务在 Kanban 看板上的样子，带一行摘要和指向笔记的链接。

卡片故意写得很短。所有重要内容都在任务的**笔记**里，因为看板每天都在变，而笔记才是记录。

## 看板

一个简单的看板有四列：**待办**、**进行中**、**已阻塞**和**完成**。两条规则让它保持诚实：

1. **“进行中”只放此刻有人在做的事。** 停滞的卡片回到“待办”或“已阻塞”。
2. **看板在变更的同一步更新。** 开始、完成、阻塞：卡片在那一刻就变，并附日期和证据。

## 任务笔记

每份笔记都有相同的章节。它们回答执行者会问的问题：

| 章节 | 问题 |
|---|---|
| 问题 | 这为什么存在？ |
| 要做什么 | 具体改什么？ |
| 在哪里 | 哪些文件或区域？ |
| 关联规则 | 这里适用哪些决定和规则？ |
| 验收 | 怎么知道做完了？ |
| 问题清单 | 还有什么依赖人的决定？ |

[任务模板](copie-o-metodo.md)自带这套结构。

## “已调研”是什么意思

任务只有在**已调研**时才**开始**：笔记中已经列全了所有需求，并且对负责人**没有未解决的问题**。此时卡片获得标签 `#explorada`。

这避免了最常见的浪费：有人开了头，做到一半发现缺一个决定，然后停下。

:::nota[未解决的问题会阻止开始]
如果笔记里还有一个没有答案的问题，任务就**不会**进入执行。它会进入一次**调研**：有人阅读代码和文档，写下缺少的内容，并给出带选项和建议的问题。只有答案到手，标签才会加上。
:::

## 一个简短的例子

请求：“我希望登录支持 SSO”。

1. 请求变成史诗“企业登录”和任务 ATV-001。
2. 没有标签，ATV-001 要经过调研。调研的人发现两件事：登录文件，以及一个疑问（“用哪个提供方？”）。
3. 他把两件事写进笔记，并给出选项 A、B、C 和一个建议。
4. 负责人回答“B”。答案写入笔记，卡片获得 `#explorada`。
5. 直到现在，ATV-001 才能进入一个[轮次](a-rodada.md)。

## 发现何时变成任务

每个测试发现、已开的 issue 或生产中看到的错误都走同一条路：变成一个带卡片的任务，绝不只留在对话里。这样什么都不会丢，看板就是“还缺什么”的唯一清单。
