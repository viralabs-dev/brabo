# Ошибки, которые мы уже совершили

**Для кого:** для тех, кто хочет избежать самого дорогого пути.

**После прочтения вы сможете:** узнать девять ловушек набора репозиториев, прежде чем в них попасть. Каждый урок понятен сам по себе и указывает на публичный источник.

## 1. Копирование списка репозиториев вручную
- **Симптом:** раздел «Repositórios do Brabo» был в 14 местах в 11 разных вариантах. README `brabo-ci` утверждал, что он ни от кого не зависит, но он читает данные двух других репозиториев.
- **Причина:** копирование без единого источника и без проверки.
- **Правило, которое осталось:** один источник (`repos.yml`), остальное генерируется, а проверка отклоняет расхождения. [ADR 0281](../../adr/0281-o-mapa-dos-repos-tem-uma-fonte-so.md).

## 2. Чтение `dev` соседей «на сейчас»
- **Симптом:** один и тот же PR без нового коммита переходил из зелёного в красный. В `dev` соседей приходилось около 56 слияний в день.
- **Причина:** генератор документации клонировал вершину `dev` каждого соседа в момент запуска.
- **Правило, которое осталось:** читать соседей через блокировку SHA, которую обновляет только бот. [ADR 0274](../../adr/0274-os-gerados-leem-os-irmaos-por-uma-trava-de-shas.md).

## 3. Измерение переводов всех сразу
- **Симптом:** 19 из 28 красных PR за две недели не были виноваты в том, что изменили.
- **Причина:** паритет переводов суммировал документацию всех репозиториев, и чужое слияние меняло итог.
- **Правило, которое осталось:** каждый репозиторий измеряет только собственную документацию. [ADR 0273](../../adr/0273-a-paridade-de-traducao-mede-so-a-doc-do-brabo.md).

## 4. Порядок слияния «в голове» у кого-то
- **Симптом:** `dev` infra стала красной между двумя слияниями в разных репозиториях.
- **Причина:** в GitHub нет зависимостей между репозиториями, а порядок нигде не был записан.
- **Правило, которое осталось:** PR объявляет `Depende-de: владелец/репо#N`, и проверка ждёт; при продвижении порядок выводится из слоёв. [ADR 0276](../../adr/0276-a-pr-declara-de-que-pr-depende-o-merge.md) и [ADR 0284](../../adr/0284-a-promocao-infere-as-dependencias-pela-ordem-dos-repos.md).

## 5. Пин политики без читаемой версии
- **Симптом:** 5 разных SHA в 11 репозиториях и пины, замороженные без предупреждения.
- **Причина:** комментарий пина говорил `# dev` или ничего, а Dependabot обновляет только пин, комментарий которого - версия.
- **Правило, которое осталось:** комментарий - `vX.Y.Z`, SHA - от этого тега, а проверка это контролирует. [ADR 0280](../../adr/0280-o-pin-do-brabo-ci-aponta-para-uma-tag.md).

## 6. Тег или PR через `GITHUB_TOKEN`
- **Симптом:** PR продвижения становился «готовым к слиянию», хотя проверка продвижения не запускалась, а тег так и не опубликовал релиз.
- **Причина:** GitHub не запускает workflow от событий, созданных `GITHUB_TOKEN`.
- **Правило, которое осталось:** всё, что должно запускать другой workflow, использует токен GitHub App. [Уроки CI, №3](../../explanation/licoes-do-ci.md).

## 7. `if:` в обязательном задании
- **Симптом:** проверка оставалась зелёной после смены базы PR.
- **Причина:** статус привязан к коммиту и имени; пропущенное задание оставляет старый зелёный статус, а `skipped` считается зелёным.
- **Правило, которое осталось:** обязательное задание всегда выполняется, а фильтр находится внутри него. [Уроки CI, №2](../../explanation/licoes-do-ci.md).

## 8. Пин продукта отстаёт от последнего релиза
- **Симптом:** продукт остался с тегом без релиза, дважды подряд (v2.1.0 и v2.1.1).
- **Причина:** компонент выпустил релиз между слиянием в `main` и проставлением тега, и блокировка отклонила.
- **Правило, которое осталось:** пин поднимает бот, а выход - слить его PR и выпустить патч продукта. [Релиз продукта](../../explanation/release-do-produto.md).

## 9. Перезапись всего lock-файла при подъёме контракта
- **Симптом:** CI `brabo-broker` сломался после повышения версии контракта.
- **Причина:** `pnpm install` пересоздал весь lock-файл, а не только записи контракта.
- **Правило, которое осталось:** скрипт подъёма прививает к старому lock-файлу только блоки контракта и отказывается от остального. [`subir-contracts.sh`](https://github.com/viralabs-dev/brabo-ci/blob/dev/scripts/ci/subir-contracts.sh).

> **Для вашего проекта:** закономерность всех девяти уроков одна. То, что не генерируется и не проверяется машиной, расходится. Прежде чем делить, решите, какая проверка будет следить за каждым ребром.
