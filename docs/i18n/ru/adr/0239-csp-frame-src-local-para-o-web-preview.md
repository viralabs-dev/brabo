# ADR 0239 — Локальный CSP `frame-src` для Web preview результата

- **Статус:** принято
- **Дата:** 2026-11-02
- **Пересматривает:** CSP из `docker/web/nginx.conf` (унаследованный от [ADR 0058](0058-csp-fechado-na-api-e-escopo-de-projeto-contido.md)), только в части фреймов.

## Контекст

AT-685 показывает результат проекта, запущенный на машине пользователя, в
`iframe` внутри Brabo. Без `frame-src` CSP откатывается к `default-src 'self'`, и
браузер блокирует фрейм.

## Решение

1. CSP nginx в web получает `frame-src http://localhost:* http://127.0.0.1:*`.
   Ни `https:`, ни внешнего домена.
2. Компонент принимает только URL, проходящий `urlLocalSegura`; внешний URL
   отклоняется, и экран называет причину текстом.
3. `sandbox` фрейма минимален: `allow-scripts allow-same-origin`. Эти два
   вместе безопасны лишь потому, что origin фрейма (`localhost:<порт>`) отличается
   от origin Brabo: фрейм не достаёт до DOM, cookie и storage Brabo.
   `allow-forms`, `allow-popups` и `allow-top-navigation` остаются вне.
4. `frame-ancestors 'none'` и `X-Frame-Options: DENY` не меняются: они по-прежнему
   запрещают ДРУГИМ встраивать Brabo.

## Последствия

- Остаточный риск: встроенная локальная страница выполняет произвольный код самого
  проекта пользователя, на его машине, со своим origin. Если Brabo
  отдаётся на `localhost` на ТОМ ЖЕ порту, что и результат, изоляция origin исчезает;
  поэтому результат не может занимать порт Brabo.
- Установка с Brabo на удалённом сервере увидит `iframe`, указывающий на
  `localhost` браузера, а не сервера; такова задуманная семантика.
