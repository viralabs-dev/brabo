# ADR 0230 — Runner импортирует API-ключ LLM, который у пользователя уже есть на машине

## Статус

**Принято.** 2026-10-29 (AT-611, EP-026, решения владельца от 29.10). Тема: `runner`.
Дополняет, не редактируя их, [0158](0158-o-id-da-chave-mestra-gravado-no-envelope.md) (envelope с
`key_id`), [0154](0154-chave-de-dispositivo-de-maquina.md) (ключ устройства
машины) и [0050](0050-credencial-sempre-cifrada-verificacao-explicita.md) (хранить и проверять —
два разных предмета).

## Контекст

Пользователь, уже работающий с Claude Code, Codex, OpenCode, Kilo Code CLI или Hermes, имеет API-ключи
LLM на диске собственной машины и сейчас вводит каждый заново на экране
учётных данных. Api работает в контейнере и до этого диска не дотягивается; дотягивается
`brabo-runner`. Импорт — эффект над секретом, поэтому нужно явное
согласие на каждый ключ, и он никогда не происходит молча.

## Решение

1. **Только API-ключ.** OAuth-токен подписки (Claude Pro/Max, ChatGPT/Codex, Copilot)
   НЕ импортируется: условия поставщиков привязывают его к официальному клиенту, а использование его в
   другом продукте рискует аккаунтом владельца. Команда перечисляет найденное как «вход по
   подписке, не импортируется — создайте API-ключ» и называет причину.
2. **Чтение — только интерактивного runner** (`brabo-runner credentials import`, TTY
   обязателен, выбор по элементам). Api никогда не читает диск пользователя.
3. **Маршрут `POST /runner/llm-credentials`**, `@RequirePatAuth()` + `PatAuthGuard`, который
   делегирует ТОМУ ЖЕ `UpsertUserCredentialUseCase` (envelope с `key_id`) для пользователя —
   владельца учётных данных. Так как у маршрута нет `:projectId`, guard отклоняет с 403 любые
   учётные данные, привязанные к проекту; всякий PAT проектный, поэтому на практике проходит только ключ
   устройства МАШИНЫ. Это первый маршрут, в котором учётные данные машины пишут
   секрет пользователя.
4. **Никогда не перезаписывает без подтверждения:** существующие учётные данные провайдера
   без `substituir: true` — это 409 `credencial_existente`, без затрагивания существующих.
5. **Значение никогда не попадает в лог, URL, событие, исключение и ответ.** Лог аудита несёт
   провайдера и `origem` (инструмент и путь); ответ — `{ provider, substituida }`.
6. Маршрут только хранит (ADR 0050); тест соединения — отдельное действие
   (`POST /users/me/credentials/:provider/test`), на стороне клиента.
7. Keychain macOS оставлен для отдельного среза.

## Последствия

- Скомпрометированное устройство машины сможет записывать (а с `substituir` —
  заменять) ключ LLM владельца. Потолок — отзыв ключа (ADR 0201) и 409 как
  значение по умолчанию.
- Импортирующий видит на экране учётных данных ту же строку, что у любых учётных данных.
- Новый импортируемый инструмент — это новый reader в runner, без изменения маршрута.
