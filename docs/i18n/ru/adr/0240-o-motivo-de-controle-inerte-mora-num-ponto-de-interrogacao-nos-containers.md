# ADR 0240 — Причина неактивного элемента управления может жить в активном «?» на странице Containers

- **Статус:** принято
- **Дата:** 2026-11-02
- **Пересматривает:** [ADR 0064](0064-escopo-de-area-na-cascata-e-o-binding-de-agente-global.md), только в правиле «причина неактивного элемента управления называется видимым ТЕКСТОМ», и только для страницы Containers.

## Контекст

ADR 0064 велит называть причину неактивного элемента текстом, потому что `title`
и tooltip на элементе `disabled` не открываются. На странице Containers каждая строка
громоздила до четырёх фраз («Никогда не провизионирован…», «Образ не определён…», broker…)
под тремя кнопками-иконками, и владелец (превью v6, 02.11) предпочёл чистую
строку. ADR 0064 защищает то, чтобы причина была ДОСТУПНА, а не то, чтобы
она занимала ячейку.

## Решение

1. В `AcoesDoContainer.tsx` причины неактивности по строке уходят в ОДИН `Ajuda`
   («?»), с темой «Почему действия недоступны», рядом с
   кнопками. «?» — АКТИВНАЯ кнопка (не `disabled`): открывается по клику, с клавиатуры и
   по наведению, и потому причина остаётся достижимой при отключённых кнопках.
   Без причины «?» нет.
2. Причина по РОЛИ по-прежнему называется один раз, текстом, вверху страницы.
3. Исключение действует ТОЛЬКО для Containers. На любом другом экране причина
   неактивного элемента остаётся видимым текстом (например, подсказка «Я
   готов» в composer).

## Последствия

- `design/COMPONENTS.md`, раздел «Ajuda», фиксирует исключение и его предел.
- Распространение на другую страницу требует нового ADR, а не перечитывания этого.
