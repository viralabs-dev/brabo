# ADR 0254 — Документация каждой области живёт в её корне

- **Статус:** принято
- **Дата:** 2026-11-04
- **Тема:** `docs`
- **Ссылается на:** ADR [0216](0216-quatro-idiomas-com-pt-br-como-fonte.md), [0252](0252-o-brabo-vira-um-conjunto-de-repositorios.md) и [0253](0253-o-site-de-docs-deixa-o-docusaurus.md). Ни один из них не редактируется.

## Контекст

0252 разделяет Brabo на репозитории по областям, а 0253 дал сайту собственный генератор. Если вся документация остаётся в `docs/`, каждый новый репозиторий родится без документации собственного кода, а бизнес-правила (RN) живут в трёх больших файлах, смешивающих области (решение владельца от 02.11.2026, AT-688, вопрос 11, подтверждено 04.11, AT-693).

## Решение

1. **Документация каждой области живёт в `<корень>/docs/`.** Список корней — в `scripts/docs/raizes-de-doc.mjs`; `docs/` остаётся агрегатором («продукт»).
2. **Сайт — это ОБЪЕДИНЕНИЕ деревьев** корней: каждый файл сохраняет ТОТ ЖЕ относительный путь, что имел в `docs/` (`reference/permissions.md` становится `apps/api/docs/reference/permissions.md`), публичный URL не меняется, а ссылки между страницами записываются в координатах ОБЪЕДИНЕНИЯ, а не диска. Повторяющийся slug между корнями проваливает проверку.
3. **RN по областям.** Каждая RN живёт в `<корень>/docs/business-rules/<корень>.md`, в корне, где находится ПЕРВАЯ ссылка `caminho:N` тела (без ссылки — первый упомянутый путь; без вообще — продукт). Нумерация ГЛОБАЛЬНАЯ и единая (следующая — максимум по сумме всех корней), а якорь `{#rn-NNN}` не меняется.
4. **`docs/business-rules.md` становится СГЕНЕРИРОВАННЫМ ИНДЕКСОМ** (строка на каждую RN со ссылкой на страницу-хозяина, чтобы `business-rules.html#rn-NNN` продолжал разрешаться). `custo.md` и `autenticacao.md` становятся ЗАМОРОЖЕННЫМИ заглушками, записанными один раз. Новая проверка: один и тот же номер RN в двух файлах проваливает проверку.
5. **Источники и проверки.** `scripts/docs/fontes.yml` (или файл, на который указывает `BRABO_FONTES`) сопоставляет логическое имя с корнем. Проверки получают `--raiz <имя>`: они выполняют ПО корню то, что зависит только от него (якоря RN, внутренние ссылки `caminho:N`, glob docmap, drift), и ТОЛЬКО в агрегаторе то, что пересекает корни (подсчёты, уникальность и индекс RN, внешние ссылки, паритет, ссылки между locales, процедуры runbook). В монорепозитории `pnpm docs:check` выполняет всё.
6. **Переводы** в `<корень>/docs/i18n/<locale>/<тот-же-путь>`; `traducao.json` остаётся ОДНИМ, в агрегаторе. Изменение, перемещающее файлы, по построению делает все переводы «устаревшими», поэтому оно вносится ДВУМЯ коммитами: самим изменением и вторым, перештамповывающим `traducao_de` SHA первого, только в тех, что были актуальны.
7. **Корпус golden-set RAG остаётся ЗАМОРОЖЕННЫМ** (ADR 0132): смена места документации не может переписать базовую линию.

## Последствия

- Каждый будущий репозиторий несёт собственную документацию и собственные RN; сайт остаётся один, и ни один URL не меняется.
- **Цена:** ссылка между корнями работает на сайте и даёт 404 в просмотре GitHub (путь ссылки — это путь объединения, а не диска).
- Пишущему RN нужно знать область — владельца кода; `docs:check` указывает на дублирующуюся RN, отсутствующий якорь и ссылку, которая не совпадает.
- Миграция файлов и ~13 тысяч связей между страницами — единый идемпотентный скрипт в том же PR сразу после этого ADR.
