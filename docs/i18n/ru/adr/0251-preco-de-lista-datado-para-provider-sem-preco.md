# ADR 0251 — Датированная в коде прайс-цена для провайдера, не сообщающего цену

- **Статус:** принято
- **Дата:** 2026-11-03
- **Ссылается на:** ADR [0042](0042-catalogo-vivo-ciclo-de-vida-do-modelo-e-preco-auditavel.md) (ручная курация, цена, зафиксированная в метеринге). Ни один ADR не редактируется.

## Контекст

`/v1/models` у Anthropic не несёт цену и не сигнализирует рассуждение в Brabo: 13 из 14 синхронизированных моделей пришли с ценой 0 и `supports_reasoning = false`. Расход с нулевой стоимостью без предупреждения, и AT-676 никогда не включала рассуждение.

## Решение

1. Провайдер, чей API не сообщает цену, читает ПРАЙС-цену из единой таблицы производителя (`precos-do-fabricante.ts`, RN-965, со ссылкой и датой источника в каждой строке), ТОЙ ЖЕ, что на экране подсказки, а теперь используемой и синхронизацией. `listModels` сопоставляет по ID и, если не нашёл, по ID без суффикса даты. ID вне таблицы остаётся без цены.
2. Синхронизация не меняется: `manual_pricing` по-прежнему побеждает удалённый каталог; прайс-цена входит только в строку без ручной цены.
3. `supportsReasoning` берётся из `capabilities.thinking` SDK, с семейством как запасным вариантом.

## Последствия

- Таблица стареет: обновление — это правка `precos-do-fabricante.ts` и `conferidoEm`, а цена новой модели до тех пор — курация.
- Источник один: экран подсказки и синхронизация не расходятся.
