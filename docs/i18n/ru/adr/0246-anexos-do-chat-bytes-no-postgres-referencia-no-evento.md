# ADR 0246 — Вложения чата: байты в Postgres, ссылка в событии, зрение по capability

- **Статус:** принято
- **Дата:** 2026-11-03
- **Ссылается на:** ADR [0041](0041-base-openai-compativel-e-contrato-de-llm-providers.md) (capability без доказательства — `false`), [0113](0113-pasta-local-anexada-via-navegador-vira-chunks-scope-local.md) (JSON-загрузка, «отклонять, никогда не усекать») и [0152](0152-backup-de-volumes-contra-compose.md) (что входит в бэкап). Ни один из них не редактируется.

## Контекст

AT-715 (EP-031): ни один чат агента не принимает файл. Владелец ответил на 11 вопросов обследования 02.11: текст/код и изображение; 5 МБ на изображение, 512 КБ на текст, 4 на сообщение; Postgres; живёт вместе с сессией; изображение уходит в LLM только на ходе, в котором пришло; видит любой `viewer`; без антивируса; чат без агента — вне. Event log append-only, поэтому байты не могут жить в нём.

## Решение

1. **Байты в Postgres.** Таблица `chat_attachments` (`bytea`, FK `cascade` на проект и сессию), без UPDATE. `pg_dump` бэкапа уже её покрывает, а RBAC — проектный. Ничего не идёт на диск или в worktree, поэтому нового сдерживания пути нет (RN-092/095).
2. **Ссылка в событии.** `chat.message` записывает `anexos: [{id, nome, mime, tamanho}]`, и engine получает тот же список; байты покидают базу только когда api собирает вызов провайдеру (lane L2) или когда кто-то читает вложение.
3. **Зрение по capability.** `ChatMessage.content` принимает `string` или части `text`/`image`, а `LLMProviderCapabilities.vision` рождается `false` у одиннадцати провайдеров (ADR 0041; включает его только реальный smoke). Engine отправляет вложение по id в `llm-turn` (`{type:'anexo',id}`), а api его разрешает: изображение уходит только при провайдере И модели со зрением; иначе превращается в текст-предупреждение (RN-989). У Anthropic и Ollama свой формат (`image` base64, `images`), без доказательства capability.
4. **Кто видит.** Любой `viewer` проекта, тот же охват, что у `GET .../events`. Чужое — 404.
5. **JSON с base64, а не multipart.** 5 МБ превращаются в ~6,7 МБ, в пределах тела 10 МБ, без `multer` и нового парсера; это образец загрузки RAG.
6. **Тип по байтам.** Сигнатура для png/jpeg/gif/webp; текст — валидный UTF-8 без NUL. SVG не принимается как изображение (упал бы как текст и отдаётся с `nosniff`/`attachment`).

## Последствия

- **Заявленный пробел: без антивируса.** Байты никогда не исполняются (лежат в `bytea` и отдаются с `nosniff` и `attachment`), но никто их не сканирует; ClamAV стал бы новым сервисом и решением владельца. Зафиксировано в `docs/security-surface.md`.
- `pg_dump` растёт с вложениями; измерить позже (хранение — жизнь сессии, без очистки).
- JSON-тело загрузки 10 МБ — потолок маршрута, и каждый запрос несёт весь файл в памяти.
