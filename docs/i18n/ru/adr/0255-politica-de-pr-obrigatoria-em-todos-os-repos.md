# ADR 0255 — Политика PR обязательна во всех репозиториях, а PR регенерации от бота освобождается от лестницы в dev

- **Статус:** принято
- **Дата:** 2026-11-05
- **Тема:** `git`
- **Ссылается на:** ADR [0236](0236-o-dependabot-dispensa-revisao-na-dev.md) и [0252](0252-o-brabo-vira-um-conjunto-de-repositorios.md), а также активности AT-726 и AT-733. Ни один из них не редактируется.

## Контекст

С разделением на репозитории (0252) проверки `Política de branches` и `Escada de aprovação` лишь сигнализировали: ни один ruleset их не требовал, так что PR, красный по ним, всё ещё можно было смержить. Три репозитория (`brabo`, `brabo-qa`, `brabo-infra`) не имели даже ruleset против force push. А PR, которую GitHub App `viralabs-dev-brabo` открывает по расписанию для регенерации генерируемых файлов (AT-726), каждые 6 ч ждала бы человеческого одобрения. Решения владельца от 05.11.2026.

## Решение

1. **`Política de branches` и `Escada de aprovação` — ОБЯЗАТЕЛЬНЫЕ (REQUIRED) проверки** в ruleset `dev` и `main` всех 11 репозиториев `viralabs-dev/brabo*`.
2. **`brabo`, `brabo-qa` и `brabo-infra` получают ruleset «main e dev sem force push»**, который у остальных уже был.
3. **PR GitHub App `viralabs-dev-brabo` из фиксированной ветки `chore/regenera-gerados` с целью `dev` освобождается от лестницы**; распознаётся по автору И ветке (обоим), по образцу ADR 0236. `main` по-прежнему проходит всю лестницу.

## Последствия

- PR, не прошедшую политику или лестницу, больше нельзя смержить ни в одном репозитории набора.
- Регенерированные генерируемые файлы попадают в `dev` без человеческого ожидания; остальные проверки `dev` по-прежнему служат ревью, а продвижение в `main` по-прежнему требует одобрения.
- Одного автора или одной ветки для освобождения недостаточно.
