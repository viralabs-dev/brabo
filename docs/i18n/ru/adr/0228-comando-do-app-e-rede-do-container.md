# ADR 0228 — Контейнер проекта запускает приложение по объявленной команде и публикует порт только на loopback

## Статус

**Принято.** 2026-10-29 (AT-610 и AT-608, EP-030; решения владельца от 29.10).
Тема: `container`. Пересматривает, не редактируя их,
[0130](0130-broker-de-container.md) (ЗАКРЫТАЯ spec без
поля сети) и
[0213](0213-o-entregavel-roda-na-maquina-pelo-compose-da-infra.md) (Decision 1:
«broker НЕ публикует порт»). Сосуществует с
[0189](0189-o-piloto-automatico.md) и
[0229](0229-instancia-de-qa-efemera-com-servicos-declarados-pela-infra.md).
Эта lane фиксирует КОНТРАКТ `packages/docker-port` и broker; api, engine,
runner и web идут позже и реализуют свою сторону.

## Контекст

Контейнер проекта поднимается с `sleep infinity`, и приложение работает только во время
теста QA. Опубликованный порт без слушающего процесса не показывает никакой страницы, а
владелец попросил настраивать порты, DNS и `extra_hosts` на контейнер
(AT-608), с приложением, объявленным Infra (AT-610).

## Решение

1. **Команда приложения (`comandoDoApp`, необязательная).** Infra объявляет её
   (`run.app` в `artifact.run_instructions`); api отдаёт её в
   `container-spec`, а broker НИКОГДА не читает её из тела запроса. До 300
   символов, без `\n`, `\r` и NUL. С ней `argsDeCriacao` заменяет
   `sleep infinity` на КОНСТАНТНЫЙ супервизор (`SUPERVISOR_DO_APP`), с
   командой как позиционным АРГУМЕНТОМ (`$1`, образец RN-807), никогда не
   конкатенируемой: приложение стартует в фоне, с логом в `/tmp/brabo-app.log` и
   кодом выхода в `/tmp/brabo-app.exit`, а PID 1 остаётся `sleep infinity`.
   Умершее приложение остаётся мёртвым. Без поля `docker run` байт в байт
   такой же, как сегодня (доказано тестом).
2. **Порты.** `portas: [{ host, container, protocolo: 'tcp' }]`, всегда
   `-p 127.0.0.1:H:C` (интерфейс — константа адаптера, без опции).
   Host от 1024 до 65535, вне портов установки (3000, 4000, 5173, 5432,
   7474, 7687, 8088, 8090, 11434), не более 10, без дубликатов, и отклоняется
   при сети `none`. Меняется только форма СДЕРЖИВАНИЯ: сеть `egress` уже достигала
   опубликованных портов машины (ADR 0189), а публикация — только на loopback.
3. **DNS и `extra_hosts`.** `dns` — список литеральных IP v4/v6 (до 3);
   `hostsExtras` — `{ nome, ip }` (до 10), с именем в `[a-z0-9.-]` (до 253,
   без точки/дефиса по краям), никогда `localhost` и не имя сервиса
   установки, и литеральный IPv4 (`:` в IPv6 неоднозначен в `--add-host`).
   Также отклоняются при сети `none`.
4. **`inspect`** теперь читает `NetworkSettings.Ports` и возвращает
   `portasPublicadas` в НАБЛЮДАЕМОМ состоянии; то, что объявила Infra, остаётся
   другой колонкой (RN-468).
5. **`DockerPort` остаётся с пятью операциями.** Новые поля принадлежат
   SPEC; новая операция не рождается. Смена команды, портов, DNS или
   hosts действует только в ПЕРЕСОЗДАННОМ контейнере (`start` идемпотентен); действие
   пересоздания и одобрение — за lane api.
6. **Вне этой lane:** `runner` (capability в `join`, позже), страница,
   действие `container_recreate` и одобрение команды — владелец решил, что
   включённый автопилот освобождает от клика, а без него PR Infra с
   `run.app` требует человеческого одобрения.

## Последствия

- 0213 перестаёт действовать в фразе «broker НЕ публикует порт»; остальное действует.
- У контейнера появляется долгоживущий процесс, запускаемый продуктом, с
  сдерживанием любого `exec` (`--cap-drop ALL`, `--user`, pids/память).
- Отсутствие `setsid` в образе не мешает приложению: супервизор откатывается на прямой `sh`.
