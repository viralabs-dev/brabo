    What Brabo Is

    Brabo runs the full lifecycle of an application, from brief to deploy, with a team of AI agents working over a real git repository. Final authority is yours, and that is a property of the architecture, not a slogan. Each agent handles one role (Creative, PO, Architect, devs, QA, SecOps) and nothing with an external effect happens without passing through the project's policy.

    What sets it apart from a code assistant

    • Nothing with an external effect happens on its own. Command, commit, push, PR, merge and token spend are born as a proposed_action and pass through the policy, where deny always beats allow. Not even the policy unlocks a merge into a protected branch.
    • The agent is not trustworthy by construction. The limits are structural: an iteration ceiling, a budget that refuses the call, a closed catalog of what each agent may do. A prompt is not a guarantee; code is.
    • Everything is recorded and immutable. The event log is append-only, and it is what makes cost auditable and evidence traceable.
    • The team improves with you in the loop. The Psychologist and Anamnesis propose adjustments to the agents' instructions, and each one only counts with your approval.

    One turn, start to finish

    sequenceDiagram
  participant U as Você
  participant W as web
  participant A as api
  participant E as engine
  participant L as LLM

  U->>W: abre uma sessão
  W->>A: POST /sessions
  A->>A: grava session.created (event log + outbox)
  A-->>E: Oban consome a outbox
  E->>E: sobe o SessionServer, monta o contexto (Harness)
  E->>L: turno
  L-->>E: "quero rodar esta ferramenta"
  E->>A: vira proposed_action
  A->>A: política: IAM → autonomy → permissions.json
  A-->>U: pede aprovação (ou aplica um teto)
  U->>A: aprova
  A-->>E: executa
  E->>A: evento imutável
  A-->>W: broadcast — o painel atualiza
