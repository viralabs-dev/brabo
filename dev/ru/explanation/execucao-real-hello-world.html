    Реальное выполнение — hello world

    Запись от 5 августа 2026 г.: описывает Brabo на ту дату

    Первый раз, когда цепочка агентов прошла от начала до конца с моделью через API, в новом проекте с настоящим репозиторием на GitHub. Цель была узнать, что ломается при настоящем использовании. Это не официальное измерение Фазы 13b, потому что engine несколько раз перезапускали по ходу.

    Впервые цепочка агентов прошла от начала до конца с моделью через API вместо локального Ollama. Новый проект (Hello API), настоящий репозиторий на GitHub, provider OpenRouter, модель ~deepseek/deepseek-v4-flash-latest.

    Целью было не сдать hello world. Целью было выяснить, что ломается, когда продуктом пользуются так, как пользовался бы пользователь, — и этого он дал в изобилии.

    Это выполнение НЕ является официальным измерением FASE 13b

    Был перезапуск engine посередине, несколько раз, чтобы загрузить исправления, которых потребовало само выполнение. Критерий "ноль перезапусков" потерян, и таблица ниже намеренно измеряет неровный прогон. Значимое измерение ещё предстоит сделать, когда всё уже исправлено и без прерываний.

    Шестнадцать находок

    Пронумерованы в порядке появления. Исправленные были решены пользователем, одна за другой.

    Исправлены в этом выполнении

    # что где оказалось
    4 мастер показывал brabo/<slug> как место назначения репозитория, с захардкоженным brabo/ — api создаёт в createForAuthenticatedUser открыто
    6 подготовка падала, а экран навсегда оставался в "Trabalhando…", с нулём событий открыто
    8 bootstrap умирал на каждом новом проекте GitHub: пустой репозиторий отвечает 409 во всём Git Data API, а provider обрабатывал только 404 PR #125
    — фейковый GitHub отвечал 404 там, где настоящий отвечает 409, — suite оставалась зелёной при сломанном продукте PR #125
    — бесплатный тариф не защищает ветку в приватном репозитории, и выбор не предупреждал PR #125
    13 ни один агент не мог использовать provider с учётными данными: ход искал ключ по slug агента в колонке UUID PR #126
    14 сбой хода становился пустым agent.response в журнале, с причиной только в эфемерном broadcast PR #127
    — чат Criativo открывался пустым, не говоря, что очередь за пользователем PR #127
    12 Criativo решал технологию (GET или POST? JSON или текст?) — идентичность не говорила, что не его PR #131
    — сбой ИНСТРУМЕНТА отбрасывался через _ =: четыре правила отклонены молча PR #131
    — перезапуск engine убивал разговор, ничего не показывая на экране PR #131
    15 Anamnese без глагола для завершения: повторяла невозможный вызов до предела, на каждом тике PR #132
    16 heartbeat в 30 с убивал сессию с ожидающим handoff — работа становилась недостижимой PR #133

    Что это выполнение доказало, а что нет

    Доказало, что цепочка Criativo → PO работает с моделью через API и производит артефакт реального качества: backlog вышел с замкнутой прослеживаемостью, а DOR историй говорил "formato e detalhes técnicos definidos pelo Arquiteto" — граница, добавленная Criativo, прошла через brief и дошла до backlog.

    Доказало, что продукт глотал ошибки на трёх разных уровнях (ход, инструмент, процесс), и что именно это держало дефекты невидимыми. Все три теперь говорят.

    Не доказало Arquiteto, dev, удалённую PR и gates. Не доказало ничего о реальной стоимости полного выполнения. И не годится как измерение FASE 13b из-за перезапуска посередине.
